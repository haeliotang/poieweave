# Self-Sustaining Core — 研究现状（第 200 轮）

日期：2026-11-14
状态：持续研究中；全部为模型级/软件级证据

## 1. 研究问题

给定一个拥有能源、水处理、制造、维修和库存能力的基地，外部补给中断后，究竟是什么决定了它能生存多久，以及能否恢复并增加生产能力？

## 2. 四个内部门槛

| 门槛 | 当前可核查证据 | 主要边界 |
| --- | --- | --- |
| S1 依赖闭合 | restorer 选择：先时长、再相对消耗；快/慢与等时长对照；producer 索引修复 | 单目标 closure，无全局最优 |
| S2 长期生存 | 故障包络、库存/能源/维护边界、补货频率、对抗子集、随机采样、时间语义边界 | 修复时长语义已部分迁移；无并发调度器 |
| S3 自主恢复 | 审批矩阵、租约边界、在途撤销、事件级拒绝、时间表审批、事件驱动时间、并发占用 | 无抢占；拒绝会停止运行 |
| S4 独立验证 | 112/112 verdict、26/26 plan、130/130 mutations；能量 4/4、PV 2/2、grease 6/6、并发 2/2、时间 2/2、审批时间表 4/4 | 窄模型；非 whole-system equivalence |

## 3. 关键数值结果

### S2

- Base-05：10/15/20/30 天泵故障间隔 → 40/60/80/≥90 天。
- Base-06：56 个双故障案例，独立覆盖 25/56，联合覆盖 24/56，唯一缺口 `pump-p1,pump-p2`。
- Base-08 再生：40→60 天；50% 产出率 → 50 天。
- 2000 个 Monte Carlo 排程：中位 72 天，p10 28，p90 90。
- 负载边界：0–2 kW 材料受限（40 天）；3/4 kW 能量受限（3/1 天）。
- 冗余：泵 60→90；共享过滤器 30 `no restorer`；过滤器修复器 90；共享机器人 35；机器人修复器 90。
- 补货频率：10/20/30/60 天 → 60/50/40/30 天。
- 对抗子集：31 个子集，最小 0 天，最小集合 `filter-1`。
- 时间语义：grease 边界 4/6/8 vs 10/16/21 天；insert 边界 6/8/10/12 vs 15/20/26/31 天；能量边界不变；补货到位时 horizon 不变。
- 长修复再生（5 天修复、2–5 天故障）：Base-05 8/12/20→20/20/20；Base-08 12/18/30→31/31/31；10 天故障时间语义再次一致。

### S3

- 必需/拒绝/短租约/错误 digest 均 fail closed；批准 8 小时可达 horizon。
- 租约边界：10799 s 拒绝；10800/10801 s 接受。
- 在途撤销在窗口内取消计划；恰好结束时刻仍执行。
- 并发：一台机器人 5 小时争用；两台机器人 3 小时理想；4 小时 deadline 仅在两台时满足。
- 三修复/4 小时 deadline：1 台 7 小时 miss；2 台 4 小时 meet；3 台 3 小时。
- 审批时间表：全批准 3 receipts/30 天；day20 拒绝 2 receipts/20 天。

### S4

- 112/112 verdict、26/26 plan replay、130/130 plan mutations、86/86 reason classes、56/56 horizon reasons。
- 审批 gate 6/6；approval 证书 7 个静态案例 + 2 个时间表案例。
- 独立模型：能量 4/4、PV 2/2、grease 6/6、并发 2/2、时间 2/2。

- Rust 测试：491（库 crate 475 + 其他包 16）。

## 5. 明确未完成

- 无真实硬件、工业场地或外部专家；M9/M10 物理验收仍未执行。
- 修复时长语义尚未完全替换旧生存函数。
- 无并发调度器/抢占；多服务审批时间表尚未实现。
- 无 FMI 3.0 co-simulation，无隔离 VM 多节点故障测试。
- 证书无持久签名密钥、无第三方信任、无正式版本化。
- 所有结论不构成物理安全性、设备寿命或工业自主能力声明。
