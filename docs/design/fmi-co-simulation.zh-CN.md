# FMI 3.0 Co-Simulation 集成说明（未实现）

日期：2026-11-15
状态：设计说明；**当前代码库尚不加载 FMU，也不执行 FMI 3.0 协同仿真**

## 1. 为什么考虑 FMI

Poieweave 不应自行重建完整的工业物理仿真引擎。FMI 3.0 定义了模型交换、协同仿真和调度接口，适合把外部动态过程模型（泵、储能、热过程等）接入现有能力语义与生存分析。

目标是让 Poieweave 负责：

- 能力与资产语义
- 生存边界与恢复策略
- 执行权责与可核查证据

外部 FMU 负责：

- 连续/离散物理动力学
- 设备级状态演化

## 2. 计划中的契约

每次协同仿真应记录并可核查：

| 证据 | 内容 |
| --- | --- |
| FMU 文件摘要 | SHA-256 |
| modelDescription | FMI 版本、模型标识、变量表 |
| 变量映射 | Poie 资产/资源 → FMU 输入输出 |
| 步长与调度 | 固定步长或事件驱动策略 |
| 轨迹摘要 | 输入、输出、事件时间的规范化哈希 |
| 失败记录 | 不收敛、超时、异常状态 |

## 3. 变量映射草案

- 输入：功率设定、负载、维修动作、环境温度
- 输出：可用功率、储能 SOC、泵流量、故障标志
- 事件：设备故障、维修完成、保护跳闸

Poieweave 的 `AssetStatus`、`FailureEvent`、`SurvivalLogEntry` 需要与 FMU 事件建立显式转换，而不是隐式假设。

## 4. 调度约束

- 一个步长内不允许回滚外部 FMU 状态；失败必须显式记录
- 不允许把 FMU 输出当作已核实的外部事实
- 时间语义必须明确：瞬时修复还是完成时间推进
- 证书必须记录 FMU 摘要与调度策略，否则结论不可复现

## 5. 当前缺口

- 没有 FMU 运行时或 FMI 导入库
- 没有真实外部模型
- 没有跨进程/跨节点的时间同步测试
- 因此不能声称已支持 FMI 3.0 协同仿真

## 6. 下一步（需要外部依赖）

1. 选择一个最小的 FMI 3.0 Co-Simulation FMU（如简单储能模型）
2. 引入成熟的 FMI 导入实现，而不是自写解析器
3. 用固定步长跑通一次 trace，并与现有能量模型对照
4. 记录差异、失败与不可比之处

在此之前，FMI 路线保持为设计说明，不进入证书声明。
