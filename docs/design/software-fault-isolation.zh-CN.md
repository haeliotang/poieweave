# 软件级故障隔离测试计划（部分未执行）

日期：2026-11-15
状态：计划；仅有单进程 crash-tail 单元测试，**没有多进程/多节点故障注入**

## 1. 已有能力

- `poie-state` 的 append log 在打开时截断 crash 尾部
- 序列号回滚与 high-water mark 检查
- 单元测试覆盖单进程 crash-tail

这些**不能**证明：

- 多进程并发写入安全
- 网络分区下的一致性
- 时钟漂移对租约/审批的影响
- 磁盘写满或损坏后的恢复

## 2. 计划中的软件故障测试

| 故障 | 注入方式 | 预期证据 |
| --- | --- | --- |
| 进程崩溃 | kill -9 写日志进程 | 重开后记录完整或截断到合法边界 |
| 双写者 | 两个进程同时 append | 序列冲突显式失败，不静默覆盖 |
| 网络分区 | iptables/loopback 阻断 | 租约/审批 fail closed，不双授权 |
| 时钟漂移 | 偏移一个进程的 monotonic 基准 | 租约边界仍按真实经过时间判断 |
| 磁盘满 | 限制目录配额 | 写入失败显式返回，不产生半记录 |
| 磁盘损坏 | 截断/翻转字节 | 非尾部损坏报错，不静默丢弃 |

## 3. 证据要求

- 原始日志与退出码
- 注入方式与时间
- 重开后读出的记录/hash
- 失败时的显式错误，而不是静默降级
- 失败用例也必须保留

## 4. 隔离级别

- 同一内核双容器：仍共享内核与时钟
- 独立 VM 或独立节点：更接近真实分区
- 两者都不等于真实工业现场验收

## 5. 当前结论

多进程/多节点故障注入**未执行**。现有单进程 crash-tail 证据只能支持“本地日志可截断恢复”，不能支持分区安全或时钟安全声明。
