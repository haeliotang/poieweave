## 1. 问题

H2 的 24 个场景中，规划结果几乎是单动作泵修复；`lathe_ok` 也没有实际进入成功判定。四种方法共享同一结构求解器，因此无法区分“联合规划”与规则/短视策略。

H2b 不重跑旧 holdout，也不修改旧报告；它检验一个更窄、可证伪的问题：

> **H2b**：当同一台维护机器人必须在 4 h 内完成“母线恢复”和“泵恢复”两项竞争性修复时，截止感知的联合规划比忽略截止的规则/短视策略有更高的双目标截止成功率。

## 2. 方法（与 H2 相同实现，不改算法）

| 方法 | 说明 |
| --- | --- |
| A 联合规划 | `poie-plan::plan` + 事件后重规划；结构候选、时间/状态感知、有界失败恢复 |
| B1 任务优先级 | 固定顺序，仅在结构阻断时修复，忽略截止 |
| B2 安全库存规则 | B1 + 安全库存阈值 |
| B3 短期优化 | 每次选择最早完成目标，忽略截止 |

所有方法共用同一扰动轨迹、预算（`max_actions=20`，最多 3 次重规划）、SAP 校验路径；SAP 失败计入失败。

## 3. 场景与扰动

- 基础模型：`scenarios/base-01/model.toml`（不新增 Base 模型）
- 扰动：
  - `pump-p1` 在 `pump_failure_h` 失效
  - `bus-1` 在 `bus_failure_h` 失效
  - 初始 `electric-energy` 取 `energy_kwh`
- 参数网格：
  - `pump_failure_h ∈ {0.0, 1.0, 2.0}`
  - `bus_failure_h ∈ {0.5, 1.0, 1.5, 2.0, 2.5}`
  - `energy_kwh ∈ {0.5, 1.0, 2.0}`
- 规模：**24 场景 = 16 开发 + 8 留出**；`holdout = index >= 16`
- 种子：`0x706f696568326200`（SplitMix64，固定）
- 目标：
  - `Service("potable-water")`，deadline 4 h
  - `Restore("bus-1")`，deadline 4 h
- 成功判据：
  1. 到 4 h 时 `potable-water` 的结构前提满足（`pump-p1`/`filter-1` 可用或降级）
  2. `bus-1` 在 4 h 前已恢复（动作 `restores` 包含 `bus-1`）
  3. 最终计划通过 SAP 校验
- 所有方法只使用 `now_s` 及之前的事件；`max_lookahead_s <= 0`。

## 4. 指标

主指标：**双目标截止成功率**（按场景计）。

次指标：

- 平均完成时间
- 平均动作数
- 未达成原因
- SAP 通过率（必须 100%）
- 期末储能（仅报告）
- 决策数、非预知检查

## 5. 判定规则

在留出集上：

- A 的成功率 ≥ 最佳基线 + 15 pp，且次指标不劣于最佳基线 → **H2b 支持**
- 仅主指标严格更优但 <15 pp → **部分支持**，报告效应量与区间
- A 不优于最佳基线 → **H2b 不支持**，发布负结果

不得在看到留出集后修改场景、成功判据、阈值或方法。
